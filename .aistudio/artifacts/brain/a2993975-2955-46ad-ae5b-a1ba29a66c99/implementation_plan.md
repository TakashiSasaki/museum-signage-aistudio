# ランディングページ導入および「展示用」「編集用」モード分岐 実装計画

トップページ（`/`）をタッチパネル対応のシンプルなランディングページに刷新し、「展示用」「編集用」の2つのモード分岐ボタンを設置します。「展示用」押下時にはブラウザの全画面表示（Fullscreen API）を開始して現行のサイネージ画面（`/display`）を表示し、ESCキーまたは画面隅の戻るボタンで安全にランディングページへ復帰できるアーキテクチャを構築します。

---

## User Review & Critical Decisions

> [!IMPORTANT]
> ご提示いただいた要件に基づき、以下の設計方針で実装を進めます。

- **確定方針 1（段階的実装）**: 「編集用」画面は将来的な動画・静止画アップロードおよびテキスト編集機能を見据え、専用パス（`/edit`）と将来像を明示したプレースホルダー画面を設置します。今回の実装では「展示用」の全画面表示およびサイネージ遷移動作を主軸として完全稼働させます。
- **確定方針 2（URLパスとSPAルーティング）**: `AGENTS.md` の規定に従い外部ルーティングライブラリ（`react-router-dom` 等）は追加せず、ブラウザの History API (`pushState` / `popstate`) とハッシュのフォールバックに対応したステート駆動型ルーティングを実装します。これにより `/`、`/display`、`/edit` の各パスが直接アクセス・リロード時にも破綻なく動作します。
- **確定方針 3（全画面制御と復帰導線）**:
  - 「展示用」タップ時にユーザー操作イベント内で `element.requestFullscreen()` を呼び出して全画面化を実行。
  - ランディングページへの復帰は「ESCキー」および「サイネージ画面左上の控えめな戻るボタン（44px以上のタッチ領域確保）」の双方が常時機能します。
  - ブラウザの全画面解除イベント（`fullscreenchange`）も検知し、全画面解除時の挙動を適切に同期します。
- **確定方針 4（タッチパネル最適化）**: ランディングページはサイネージ端末（縦型4K〜各種タッチディスプレイ）の前に立ったユーザーや管理者が直感的に迷わず操作できるよう、48px以上のゆったりとしたタッチターゲットと高いコントラストを確保します。

## 1. Overview & Core Concept

- **What It Does**:
  - **トップ（`/`）**: 愛媛大学ミュージアムの格調高いビジュアルとともに、「展示用」「編集用」の2つの大型ボタンを配置したランディングページ。
  - **展示用（`/display`）**: ボタン押下で全画面化され、現行のサイネージ画面（タイムライン選択カードグリッド、Ken Burnsエフェクト、動画再生、プログレスバー、フッター）がそのまま全画面で稼働。左上に目立たない戻るボタンを配置し、ESCキーと共に入口へ戻れる安全機構を装備。
  - **編集用（`/edit`）**: 将来のメディアアップロード・テキスト指定機能の構想を整理した準備画面。ランディングページへの戻りボタンを完備。
- **Target Audience / Persona**:
  - 博物館来館者（展示用サイネージで地球・生命・宇宙・ロボティクス等の展示コンテンツを体験する来館者）
  - 学芸員・運営スタッフ（展示開始時に全画面起動を行い、将来的にコンテンツ編集・差し替えを行う担当者）
- **Key Value**:
  - 端末起動時やリロード時に即座にサイネージが暴走することなく、意図したタイミングで全画面サイネージを開始可能。
  - 編集画面用URLと展示画面用URLの境界が明確になり、今後の管理機能拡張への強固な土台を確立。

## 2. User Experience & Visual Design

### 2.1 Key User Flows

```
[ トップ画面 (Landing: /) ]
  │
  ├───▶ [ 展示用ボタン をタップ ]
  │       ├─ requestFullscreen() 実行（全画面モード起動）
  │       └─ パス /display へ遷移 ──▶ [ サイネージ画面 (現行機能完全保持) ]
  │                                     │
  │                                     ├─ ESCキー押下 または 画面隅「終了/戻る」タップ
  │                                     └─ exitFullscreen() 実行 ──▶ [ トップ画面 (/) へ復帰 ]
  │
  └───▶ [ 編集用ボタン をタップ ]
          └─ パス /edit へ遷移 ──▶ [ 編集用プレースホルダー画面 ]
                                      │
                                      └─ 「ポータルに戻る」タップ ──▶ [ トップ画面 (/) へ復帰 ]
```

### 2.2 Visual Identity & Theme

- **Aesthetic Direction**:
  - 愛媛大学ミュージアムの既存トーン（重厚なダークネイビーのラジアルグラデーション `#1b2735` 〜 `#090a0f`、白の高コントラストテキスト）を継承。
  - 伝統と品格を醸し出すフォント `Shippori Mincho`（しっぽり明朝）を基調としたタイポグラフィ。
- **Landing Page Composition**:
  - **ヘッダー/ブランドゾーン**: ミュージアムマーク（`museum-mark.png`）、愛媛大学ミュージアム デジタルサイネージポータルのタイトルと洗練されたサブコピー。
  - **メインアクションゾーン**:
    - **展示用カード/ボタン**: メイン導線。アイコン（全画面・プロジェクション風）、見出し「展示用（サイネージ起動）」、説明文「全画面でインタラクティブ展示スライドショーを開始します」。発光感のある上品なボーダーと深みのあるグラデーション。
    - **編集用カード/ボタン**: サブ導線。アイコン（ペン・メディア編集風）、見出し「編集用（コンテンツ管理）」、説明文「展示テキストや画像・動画メディアの更新（準備中）」。落ち着いたサテン調カード。
  - **フッターゾーン**: 運営情報・クレジット、およびポータルQRコード。
- **Touch Ergonomics**:
  - 各カードボタンは最低高さ `120px`、幅広で確実なタップ領域を確保し、押し間違えを防止。
  - タップ時の微小なスケール変化（`active: scale(0.98)`）と即時フィードバック（150ms以内の反応）。

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: ルーティング実装方式（外部ライブラリ vs ブラウザ標準API）**
  - *Chosen Approach*: `window.history.pushState` および `popstate` イベントリスナーによる軽量なSPAルーティング。
  - *Why*: プロジェクト規約（`AGENTS.md`）で外部ルーティングライブラリの追加が禁止されており、かつ `firebase.json` で `rewrites: [{ source: "**", destination: "/index.html" }]` が設定済みであるため、依存関係を増やさず安全に完全なパス分岐を実現可能。ハッシュ（`#/display`）直接入力にも対応する二重の堅牢性を持たせます。
  - *Alternatives Considered*: `react-router-dom`（規約違反のため不採用）。
- **Decision 2: 全画面表示（Fullscreen API）のトリガー契機**
  - *Chosen Approach*: 「展示用」ボタンの `onClick` / `onTouchEnd` ハンドラ内で直接 `document.documentElement.requestFullscreen()` を実行。
  - *Why*: ブラウザのセキュリティ仕様上、Fullscreen API はユーザーの直接的なジェスチャー（クリック・タップ）起因でのみ許可されるため、ボタン押下契機で即座に呼び出すのが最も確実。万一ユーザー環境で全画面が拒否された場合（iFrame内やブラウザ設定など）でも、画面遷移自体は正常に行われるフォールバック設計。
- **Decision 3: 現行サイネージコンポーネントの構造維持**
  - *Chosen Approach*: 現行の `HomeScreen`、`SceneContent`、`TimelineIndicator`、`ProgressBar`、Ken Burnsエフェクト、ジェスチャー操作、キーボード操作のロジックを100%保持し、サイネージ表示モード用のサブコンポーネント（またはモード別ビュー）として整流化。
  - *Why*: 既存の入念なアニメーションや縦型4K表示の最適化資産を一切損なわないため。

### 4.2 State & Routing Specification

- **ルーティング同期ステート**:
  - `currentRoute`: `'/'` | `'/display'` | `'/edit'`（初期値は `window.location.pathname` またはハッシュから判定）
  - `navigate(toPath)`: `window.history.pushState({}, '', toPath)` を発行しステートを更新。
  - `popstate` リスナー: ブラウザの戻る/進むボタンに自動追従。
- **展示モード管理**:
  - `enterExhibition()`:
    1. `document.documentElement.requestFullscreen().catch(...)` を実行
    2. `navigate('/display')`
  - `exitExhibition()`:
    1. `document.fullscreenElement` が存在する場合は `document.exitFullscreen().catch(...)`
    2. `navigate('/')`
  - ESCキー検知: `keydown` で `Escape` が押された際、展示画面（またはサイネージホーム）にいる場合は `exitExhibition()` を発火。
  - 画面隅戻るボタン: 展示画面の左上（邪魔にならない半透明のアイコンボタン）に設置し、タップで `exitExhibition()` を実行。

### 4.3 Verification & Quality Assurance Strategy

1. **リンティング & ビルド検証**: `npm run lint` / `npm run build` による構文・型整合性チェック。
2. **ルーティング遷移検証**:
   - `/` にアクセス時、ランディングページが表示されること。
   - 「展示用」クリック時、全画面が要求され `/display`（サイネージ画面）に遷移すること。
   - 「編集用」クリック時、`/edit`（編集案内画面）に遷移し、「戻る」で `/` に戻れること。
   - 展示画面中にESCキーまたは画面左上の戻るボタンを押下した際、全画面が解除され `/` に安全に戻ること。
3. **既存機能の完全保持**:
   - 宇宙・バイオ・ロボティクス・エネルギーの4タイムライン選択、Ken Burns画像効果、動画自動再生、プログレスバー、スワイプ/キーボード操作が `/display` 内で従来通り滑らかに稼働すること。
