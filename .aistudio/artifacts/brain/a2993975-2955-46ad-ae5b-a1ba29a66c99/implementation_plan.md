# デジタルサイネージ編集画面（/edit）およびコンテンツ動的更新 実装計画

展示用サイネージ画面（`/display`）に表示されている「上部ヘッダー文字列」「フッター文字列（タグ・施設名・ロゴ・QRコード）」および「4つのデジタル展示（静止画・動画・タイトル・詳細解説テキスト）」を、ブラウザ上で直感的に編集・差し替えできる編集用管理画面（`/edit`）を構築します。編集内容は外部クラウドを用いず、ブラウザローカルストレージ（IndexedDB）に安全に保持し、リロードしても維持され、いつでもワンクリックで初期状態へ復元できます。

---

## User Review & Critical Decisions

> [!IMPORTANT]
> ユーザーヒアリングで確定した仕様および重要な技術決定事項です。

- **確定方針 1（編集対象の網羅）**:
  - **展示画面全体設定**: 上部メインタイトル（初期値: `NEXUS Signage`）、サブタイトル（初期値: `コンテンツを選択してください`）、フッターロゴ画像、フッタータグライン（初期値: `Museum of Science & Technology`）、フッター大型文字列（初期値: `NEXUS`）、フッターQRコード画像および案内テキスト。
  - **4つのデジタル展示（展示1〜4）**: 各展示のホームカード表示名・概要文、シーン1（静止画像・タイトル・詳細解説文）、シーン2（動画・タイトル・詳細解説文）、静止画表示秒数（初期値: 15秒）。
- **確定方針 2（ストレージ・データ保持方式）**:
  - クラウド保存や外部サーバーは不要（デモ目的・コンテナ再起動で消失しても良い前提）。
  - アップロードされた高解像度画像やMP4動画のバイナリを容量制限（5MB程度）のある `localStorage` ではなく、ブラウザ標準の **IndexedDB** にBlobとしてローカル保存。
  - これによりブラウザをリロードしても編集内容やアップロード動画が保持され、容量不足によるエラーを防ぎます。
  - いつでも初期展示データへ安全に復帰できる「初期設定にリセット（工場出荷状態）」ボタンを設置。
- **確定方針 3（編集画面UIレイアウト）**:
  - **タブ切り替え式レイアウト**: 「全体設定（ヘッダー・フッター・ロゴ）」「展示1（宇宙・航空）」「展示2（バイオ）」「展示3（ロボティクス）」「展示4（エネルギー）」のタブを用意し、目的の展示を迷わず編集可能。
  - 各メディア項目には「ファイルを選択（画像/動画）」「現在のメディアのプレビュー表示」「初期メディアに戻す」ボタンを配備。
- **確定方針 4（規約遵守と既存機能完全保証）**:
  - `AGENTS.md` に従い、外部UIライブラリや外部ステートライブラリ（Redux等）は使用せず、React標準フックとプレーンCSS（`App.css`）で洗練されたミュージアムトーンのUIを構築。
  - 編集画面から即座に全画面展示をテストできる「展示用サイネージを起動」ボタン、およびトップへの戻る導線を配備。

## 1. Overview & Core Concept

- **What It Does**:
  - 学芸員やデモ担当者が、サイネージ展示内容（看板テキスト、施設ロゴ、各展示ブースの静止画スライド、紹介動画、解説文）をWeb画面上で自由にカスタマイズできる管理編集コンソール。
  - PCローカルから任意の画像（PNG/JPG/SVG）や動画（MP4/WebM）をドラッグ＆ドロップまたはファイル選択で取り込み、その場ですぐに展示用画面（`/display`）へ反映。
- **Target Audience / Persona**:
  - 博物館学芸員・展示企画担当者: 展示内容の変更や特別企画展のテーマに合わせたサイネージの差し替えを容易に行いたい。
  - デモプレゼンター: 異なる企業・大学・テーマを想定したデモンストレーションを、プログラムコードを触らずに瞬時にセットアップしたい。
- **Key Value**:
  - 外部クラウド設定や認証キーが一切不要で、完全スタンドアローンかつ安全にコンテンツ差し替えデモが成立。
  - 誤って書き換えてもワンクリックで元に戻せる安心設計。

## 3. Key Product Decisions & Trade-Offs

- **Decision 1: データ永続化エンジン（IndexedDB vs localStorage）**
  - *Chosen Approach*: ブラウザ標準の **IndexedDB** を用いた非同期ストレージ管理（キー・バリュー形式の軽量ユーティリティモジュール `src/utils/signageStorage.js`）。
  - *Why*: 動画（MP4）や高解像度静止画を扱える容量（数十MB〜数GB）を確保するため。`localStorage` は約5MBの上限があり動画をBase64変換すると即座にクォータエラーとなるため、IndexedDBがブラウザ内完結の最適解。
  - *Fallback*: IndexedDBが利用できない環境ではインメモリ＋デフォルト値へ自動フォールバック。
- **Decision 2: メディアの保持フォーマット**
  - *Chosen Approach*: デフォルト素材（`space.jpg`, `Artifficial-Satellite.mp4` 等）は文字列パスのまま保持し、ユーザーがアップロードした素材のみ `File` / `Blob` オブジェクトとしてIndexedDBに保存、利用時に `URL.createObjectURL` で再生可能URL化。
  - *Why*: メモリ消費を最小化し、初期状態への復帰が非常に高速かつクリーンに行える。
- **Decision 3: コンポーネント分離と責務の明確化**
  - *Chosen Approach*: `EditorScreen` を単なるプレースホルダーから完全な編集コンポーネント群（`GeneralSettingsTab`, `ExhibitionTab`, `MediaUploader`）としてモジュール化。
  - *Why*: `App.jsx` が過大になるのを防ぎ、展示用サイネージと編集画面のコード保守性を高める。

### 4.3 Key Handlers & Interactive State Mapping

1. **メディアファイル選択 (`handleMediaUpload(path, file)`)**:
   - `<input type="file" accept="image/*|video/*">` でファイルが選択された際、即座にメモリ内BlobとIndexedDBに登録。
   - `URL.createObjectURL(file)` を生成してプレビューに即座に反映。
2. **デフォルト復元 (`handleResetMedia(path)`)**:
   - 変更された画像・動画・ロゴのみを初期出荷時のアセットパスに安全に戻す。
3. **テキストインライン更新 (`handleTextChange(path, value)`)**:
   - タイトル・サブタイトル・解説文の入力変更をステートへ即時反映。
4. **全初期化 (`handleResetAll()`)**:
   - 確認ダイアログ（モーダル）を表示後、初期設定を復元して再レンダリング。
5. **展示用画面への連携 (`SignageDisplay`)**:
   - `App.jsx` 内のサイネージコンポーネントがハードコードされた定数ではなく、`signageConfig` を参照して動的にレンダリング。

## 5. Implementation Steps

1. **ストレージ層の実装 (`src/utils/signageStorage.js`)**:
   - デフォルト設定オブジェクトの定義。
   - IndexedDB接続・保存・取得・リセットを行う関数群の実装。
2. **編集画面コンポーネント群の実装 (`src/components/editor/`)**:
   - `EditorScreen.jsx`: タブ管理（全体設定、展示1〜4）、変更保存、リセット、トースト通知。
   - `GeneralSettingsTab.jsx`: ヘッダー文字列、フッタータグライン、社名ロゴ、QRコードの編集。
   - `ExhibitionTab.jsx`: 展示タイトル・要約、シーン1（静止画＋テキスト＋秒数）、シーン2（動画＋テキスト）の編集。
   - `MediaUploader.jsx`: プレビュー・ファイル選択・デフォルト復帰を一体化した再利用可能コンポーネント。
3. **展示画面（サイネージ）の動的化 (`src/App.jsx`)**:
   - ハードコードされていた `timelines`、`timelineMeta`、フッター文字列、ヘッダー文字列を `signageConfig` からの動的参照に置換。
   - アプリ起動時に IndexedDB から設定を読み込み。
4. **スタイリングの整備 (`src/App.css`)**:
   - 編集画面用のタブ、入力フォーム、プレビューカード、アップローダー、トーストのアピアランスをミュージアムの美意識に準拠して追加。
5. **検証と品質保証**:
   - `compile_applet` / `lint_applet` による検証。
   - テキスト変更、メディアアップロード、展示画面での再生確認、リロード後のデータ保持、初期化ボタンの動作確認。
